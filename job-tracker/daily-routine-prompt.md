4. **核对**：只收录 2027 届（或面向应届生）的校招全职岗位，不收实习、社招。截止日期尽量以企业官网为准；只有聚合站来源时在 reason 里写“待核实”。不知道的官网链接留空字符串，**不要编造链接**。
5. **写入 `jobs`**（用 `batch`，每批最多 50 条；已存在的文档要带 if_version；版本冲突就重新读取再写）：
   - 新岗位：`set`，`change: "new"`，`changeAt` = 当前时间（ISO，+08:00），`firstSeen` = 今天。
   - 已有岗位截止日期变了：`update` 新的 `deadline`，`prevDeadline` = 旧值，`change: "deadline_changed"`，`changeAt` = 当前时间。
   - 已截止或 `closed: true` 的岗位重新开放或补录：`update` 新的 `deadline`，`closed: false`，`change: "reopened"`，`changeAt` = 当前时间。
   - 官网显示已关闭的岗位：`update` `closed: true`（不需要标记 change）。
   - 本次又搜到但没变化的岗位：只更新 `lastSeen` = 今天，不要改 change/changeAt。
   - 不要删除任何岗位。
6. **写 `meta/latest`**（`set`，带 if_version）：`runAt`（当前 ISO 时间）、`sourcesNote`（如“新增 5 · 截止变更 2 · 重开 1”）、`summary`（中文，3–6 行）。summary 依次写：3 天内截止且她还没投的岗位（公司 + 日期）；本次新增/重开/截止变更里最值得投的 3 个及一句理由；`status` 为“测评待做”的岗位数量提醒；需要她自己去官网核实的事项。不要提到排除名单里的岗位。

## 岗位文档字段（jobs/{id}）
- id：小写英文 slug，用公司拼音或英文名，必要时加方向，如 `mihoyo`、`bytedance-ops`、`smg-media`。同一公司同一批次的多个相近岗位合并为一条，title 里用“ / ”分隔。
- 字段：`company`、`title`、`category`（只能是：运营、市场/品牌、新媒体/内容、职能/HR/行政、管培生、其他）、`city`、`deadline`（YYYY-MM-DD，未知为 ""）、`deadlineNote`（如“招满即止”“未写截止”，有日期时为 ""）、`applyUrl`（官网投递页）、`match`（1–5，按与她经历的匹配度）、`reason`（一两句中文：为什么推荐、怎么投、要注意什么）、`sources`（[{name, url}]，最多 4 个）、`change`、`changeAt`、`prevDeadline`（可选）、`firstSeen`、`lastSeen`、`closed`（布尔）。

最后用两三句话汇报本次新增、变更和写入的数量。
